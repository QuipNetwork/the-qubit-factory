# Custom-circuit links for a self-hosted Qubit Factory

**Date:** 2026-06-05
**Status:** Draft — pending user review
**Repos involved:** `the-qubit-factory` (the game), `quantum-echoes` (the circuit generator)

## Goal

Let a circuit generated by `quantum-echoes` be opened in The Qubit Factory via a
URL, pre-built in the sandbox so a player can explore and run it. Host the game
ourselves on Netlify at `qbf.quip.network`.

## Background (what already exists)

The Qubit Factory is a static site (`index.html` + minified `scripts.min.js` +
`scripts/*.js` modules + assets). It already serializes circuits ("factories")
to JSON and shares them **via the clipboard**:

- Export: `Helper.copyCurrentBoard()` packs `_gateList`, `_qubitList`, `_bitList`,
  `_tiles` and writes JSON to the clipboard (Ctrl/Cmd-C; "Factory Copied").
- Import: a paste shortcut calls `Helper.importFactory(JSON.parse(clipboard))`.
- Validation: `Helper.checkImportFactory(tag)` — the tag `"freeA"` is always
  accepted; other tags must match the current scenario and its tile/gate hashes.

The factory format is visible (commented out) in `index.html` as the `INTERRUPTS`
block. Each gate is a 9-tuple:

```
[col, row, type, "free", orient, rot, flip, index, value]
```

where `rot` is an angle in **radians** (e.g. `1.5708…` = π/2). `tiles` is a flat
grid array of wire-routing codes (`-1` empty; `21–28` pipe segments; `52/55`
endpoints). Quantum gates use `q`-prefixed types: `qCreate` (qubit input),
`qControl` (control line), `qCompare` (measure/output).

The generator `quantum-echoes` produces circuits deterministically from a seed
(`src/components/certificate/QuantumCircuit.tsx`, `generateCircuit`):

```ts
interface Gate {
  moment: number;                       // time column
  qubits: [number] | [number, number];  // control first for cx/cz
  label: string;                        // H X Y Z S T RX RY | CX CZ SW
  type: "single" | "cx" | "cz" | "swap";
}
```

Defaults: 8 qubits × 28 moments. Two-qubit gates are always **adjacent** (no
crossings), which simplifies spatial routing in the game.

## Measured constraints

- Playfield is `FIELD.cols = 19 × FIELD.rows = 14`.
- The `freeA` scenario exposes **6 qubit channels** (`channelsDir`,
  `channelsCol`, `editable` are 6-element arrays) and ~17 usable moment columns
  after the input/measure columns.
- Single-qubit gates are built from real matrices:
  `getFlipMatrix(θ) = [cosθ, sinθ, sinθ, −cosθ]` (reflection) and
  `getRotMatrix(θ)` (rotation). So `Z = flip(0)`, `X = flip(π/2)`, plus `H`,
  `RX`, `RY` are representable. The engine tracks complex amplitudes
  (`imag`, `phase`, `_ampsRot/_ampsComp/_ampsFinal`), but whether `Y`, `S`, `T`,
  and `SWAP` are exactly expressible through the flip+rotate interface is
  **unconfirmed from code** and must be verified in-game.

## Decisions

1. **Conversion lives in the game.** The link carries the circuit (seed or
   QASM); `quantum-echoes` stays decoupled from the game's internal schema.
2. **Play mode:** pre-built circuit in the `freeA` sandbox to explore (no
   puzzle/win-condition logic).
3. **Two link formats**, both client-only via `#hash`:
   - `#seed=<64-hex>` — canonical, compact; loader regenerates `Gate[]` by
     porting the `generateCircuit` LCG.
   - `#qasm=<base64url(deflate(qasm))>` — general fallback.
4. **Semantic exactness is required.** No silent approximation or truncation.
   - Circuits must be generated at **≤6 qubits / ≤~17 moments** at the source so
     links carry complete circuits.
   - The generator's gate vocabulary is finalized only after in-game
     verification of `Y/S/T/SWAP`. Gates the game cannot represent exactly are
     either dropped from the generator's set or cause the link to refuse to load
     with a clear message — to be decided from verification evidence.
5. **Gate verification method:** Claude drives the game locally (developer mode,
   console, Ctrl-C export), captures each gate's encoding and amplitudes, and
   reports; the user confirms the quantum conclusions.
6. **Hosting:** new Netlify site under the **Quip Network** team, publish = repo
   root, no build step. Custom domain `qbf.quip.network` + DNS. The existing
   `CNAME` (`qubitfactory.io`) is removed/ignored for the self-hosted site.

## Architecture

```
quantum-echoes seed ──┐
                      ├─► URL #hash ─► qbf.quip.network ─► QasmLoader.js
QASM (escape hatch) ──┘                                        │
                                                               ▼
                                   CircuitGen.js / QasmParser.js  →  Gate[]
                                                               │
                                                               ▼
                                            FactoryBuilder.js → {tag:"freeA", gates, tiles}
                                                               │
                                                               ▼
                                                   Helper.importFactory(...)  → freeA sandbox
```

### New files in `the-qubit-factory` (bundle untouched)

- `scripts/CircuitGen.js` — port of `generateCircuit` (LCG kept byte-identical to
  the `quantum-echoes` source so seeds yield identical circuits).
- `scripts/QasmParser.js` — minimal OpenQASM parser for the supported subset.
- `scripts/FactoryBuilder.js` — pure `Gate[] → {tag, gates, tiles}`: assign
  qubits→channels, moments→columns, emit routing tiles, map gates via the
  calibrated table.
- `scripts/QasmLoader.js` — entrypoint: read `location.hash`, dispatch
  `seed`/`qasm`, switch scenario to `freeA`, call `Helper.importFactory`; on any
  failure show `FIELD.message`.
- `index.html` — add one `<script src="scripts/QasmLoader.js">` after the bundle.

### Changes in `quantum-echoes`

- Extract `generateCircuit` into a shared, dependency-free module (single source
  of truth for the LCG).
- Add `gatesToQasm(gates, qubits)`.
- Add a **"Play in Qubit Factory"** button on the `[seed]` page emitting
  `https://qbf.quip.network/#seed=<seed>`.
- Constrain generation to ≤6 qubits / ≤~17 moments for shareable circuits.

### Gate mapping table (to be finalized after verification)

| quantum-echoes | Qubit Factory encoding (provisional) |
|----------------|--------------------------------------|
| `RX(θ)`, `RY(θ)` | rotate gate, `rot = θ` |
| `X` | `flip(π/2)` |
| `Z` | `flip(0)` |
| `H` | confirm exact flip/rotate composition |
| `Y`, `S`, `T` | **unconfirmed** — verify in-game |
| `CX` | `qControl` on control + `X` on adjacent target |
| `CZ` | `qControl` on control + `Z` on adjacent target |
| `SWAP` | **unconfirmed** — native, or 3×CX decomposition |

## URL transport

`#hash` (no server round trip, generous length). For `#qasm`: DEFLATE via
`CompressionStream` then base64url; plain base64 fallback if compression is
unavailable. `#seed` is raw hex.

## Error handling

- Unknown/oversized/malformed hash → show `FIELD.message` toast, fall through to
  the normal title screen.
- Gate not exactly representable → per decision 4, either never generated or the
  link refuses with a clear message. No silent approximation.

## Testing

- `quantum-echoes`: golden tests that `generateCircuit` and `gatesToQasm` are
  stable per seed.
- `the-qubit-factory`: pure-function tests `seed → Gate[] → factory` against
  Ctrl-C-captured fixtures; round-trip a known circuit and compare to the
  game's own export.

## Execution order

1. **In-game gate verification** (prerequisite for exactness): build
   `Y/S/T/SWAP`, capture encodings + amplitudes, finalize the gate set.
2. Netlify site + `qbf.quip.network` serving the current game (proves hosting
   independently of the feature).
3. Loader + converter (`#seed` first, then `#qasm`).
4. `quantum-echoes` shared-generator extraction + "Play in Qubit Factory" button.
